Overview & Architecture

This page demonstrates SSR hydration with a local cache & remote sync layer: the server prints the first 100 rows into <tbody>, and ln-table hydrates them into the cache, then performs virtual windowed scrolling to fetch further pages on demand from a remote API.

Lifecycle

  1. Instant paint. The first 100 rows arrive as server-rendered <tr> elements, readable before any script runs.
  2. Hydration. On init, ln-table parses those rows and ingests them into the resident cache store (ln-data-store).
  3. Data Sync. As the user scrolls, searches, or filters, the component executes virtual windowed paging, emitting requests that the ln-data-coordinator delegates to the ln-api-connector for remote fetching.

What each control is wired to

The toolbar search and department/status popovers dispatch to ln-table. Each sortable header carries an ln-sort control whose ln-sort:change event is intercepted. The ln-data-coordinator coordinates fetching new pages from the backend (api.php) via the ln-api-connector and feeding the cached data store.

Server-side paging & Data Layer

This demo uses data-ln-table-source and data-ln-table-window to wire the table to the 3-Tier Data Layer. Scroll down to trigger remote chunk fetches dynamically.

# Аудит — ln-external-links

2026-09-10 · Опсег: `src/ln-external-links.js` (113), `README.md` (380), schema · Итерација 10/50

## Вердикт

380 линии документација за 113 линии код — и најдобро мапираната „кој што поседува"
табела во репото. Но компонентата зашива **англиски текст за screen reader** во JS,
и класата што треба да го скрие тој текст не постои во core бандлот.

## Што е добро

**„What state lives where" табелата** (`README:45-52`) експлицитно кажува кој пишува,
кој чита и каде живее секој дел состојба. Тоа е формат што вреди да се пресели во
другите компоненти.

**Табела на состојби со визуелен исход** (`README:65-70`) — вклучувајќи го случајот
„href се менува од внатрешен во надворешен", кој повеќето имплементации го
испуштаат.

**Правилна употреба на `observeAttributes`** (`:87`) за `href` — токму ln-core
примитивот наменет за компоненти со сопствен животен циклус. `ln-icon` има истата
потреба и користи сиров обсервер; тука е направено правилно.

**Не се меша во кликот.** `:45-56` само известува, никогаш `preventDefault` — па
Ctrl-клик, среден клик и влечење работат нормално. README-то го кажува тоа изречно.

**Idempotency преку DOM атрибут**, не преку JS Set (`:13`, `:27`) — маркерот
преживува повторно скенирање, MutationObserver повторно палење и рачен
`process()` повик. README-от дури го документира и како неофицијален opt-out.

## Наоди

### 🔴 EL1 — Зашиен англиски текст за screen reader, што во core бандлот станува видлив

**Каде:** `:22-25`

```js
const hint = document.createElement('span');
hint.className = 'sr-only';
hint.textContent = '(opens in new tab)';
link.appendChild(hint);
```

**Два независни проблема во четири линии.**

**(а) Зашиен кориснички текст во JS.** DOCTRINE §4: нула зашиен кориснички текст —
сè од `<template>`, `buildDict()` или `Intl`. Ова е текст што асистивната технологија
го изговара, значи е кориснички текст во најдиректна смисла. Нема `data-*-dict`
атрибут, нема `<template>`, нема начин консументот да го преведе.

Библиотеката испорачува целосен **македонски** речник во `ln-core`
(`helpers.js:1010`, види `ln-core` R6). Македонска страница добива линкови што
screen reader-от ги изговара на англиски. README §States го потврдува:
*„Hears the link text followed by '(opens in new tab)'."*

**(б) `.sr-only` не постои во core бандлот.** Класата е дефинирана точно еднаш:

- `theme/utilities/_utilities.scss:4`
- вклучена само преку `theme/ln-ashlar-theme.scss` (`@use 'utilities/utilities'`)
- `theme/ln-ashlar-core.scss` повлекува **само** 17 ко-лоцирани компонентни SCSS
  фајла — нула utilities

Консумент што испорачува `ln-ashlar-core.css` (tokenless JS substrate) добива
`<span class="sr-only">(opens in new tab)</span>` **без правило што го крие** — значи
литералниот англиски текст се исцртува видливо покрај секој надворешен линк на
страницата.

README `:59` претпоставува спротивно: *„the sr-only span is hidden"*.

Ова е истата слојна граница како `ln-core` R4 (`.hidden`), но со полош режим на
откажување: R4 тивко не крие, овде се појавува текст.

### 🟠 EL2 — Трета имплементација на „дали е надворешен линк"

**Каде:** `:8-10`

```js
function _isExternalLink(link) {
    return link.hostname && link.hostname !== window.location.hostname;
}
```

`ln-core/helpers.js:949` (`shouldInterceptLink`) веќе ја има истата споредба, со
истата слабост: **`hostname` не го носи ни портот ни протоколот**. Значи
`https://site.com:8443/x` од `https://site.com/` брои како **внатрешен** линк —
не добива `target="_blank"`, ниту `rel="noopener"`.

Правилото за 2-Consumer Lifting вели дека логика потребна на 2+ компоненти живее
во `ln-core`. Тука истата логика е препишана локално, па поправка на едното место
не го поправа другото.

### 🟠 EL3 — Мутира авторски markup без пат за враќање

`:16-27` пишува `target`, `rel`, додава дете елемент и поставува маркер. Нема
`destroy()`, нема `unprocess()`. README-то признава дека повторната обработка бара
рачно бришење на маркерот, но додадениот `<span>` останува — повторна обработка би
додала **втор** hint span ако маркерот се тргне рачно.

### 🔵 EL4 — Обликот на `window[DOM_ATTRIBUTE]` отстапува од сите други

`:108-110` пишува објект `{ process: _processLinks }`. Секаде на друго место
`window[ATTR]` е **конструкторот** што прима root (`registerComponent` го поставува
така на `helpers.js:912`). Тука е сервисен објект со метод.

Не е грешка — компонентата е глобален сервис, не per-element инстанца, и README-то
го документира како „API (global service)". Но значи дека `window.lnX` нема
униформен договор низ библиотеката.

### 🔵 EL5 — Click делегатот е на `document.body`, никогаш не се симнува

`:45` врзува траен слушач без пат за отстранување. Конзистентно со глобалниот
singleton образец, но компонентата нема ниту `_bound` знаменце како
`_fillBound` во `ln-core` — двојно вчитување би дало два делегата и **двоен**
`ln-external-links:clicked` по клик. Guard-от `window[DOM_ATTRIBUTE] !== undefined`
(`:6`) го покрива тоа, за разлика од `ln-icon` IC3.

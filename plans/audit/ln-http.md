# Аудит — ln-http

2026-09-12 · Опсег: `src/ln-http.js` (233) · `src/http-core.js` (51) · `README.md` (129) · `ln-http.schema.json` (6) · **нема** `ln-http.scss` · **нема** `ln-http-dev.scss` · Доктрина: `_doctrine.md` (337)

## Каде живее

`components/ln-http/` — **сопствена папка**, не модул во `ln-core`. Има `src/`, README и `schema.json`,
се увезува прва во `components/index.js:9`.

Но **нема host елемент, нема ниту еден `data-ln-*` атрибут** (`ln-http.schema.json:5` — `"attributes": {}`),
нема `registerComponent`, нема SCSS. Тоа е **сервисен глобал** (`window.lnHttp`, `src/ln-http.js:190`),
спакуван како компонента.

**Што значи тоа по П5** (`_doctrine.md:74`): П5 ја изземa категоријата „помошници без host" од §1 —
*„немаат host елемент; нема јазол што би носел атрибут. §1 не се крши — не е применлива."* Тоа важи и тука:
ln-http нема каде да запише состојба, па двете `Map`-и (`:60`, `:61`) **не се** „приватно огледало" по §1.

**Разликата мора да се каже изречно:** П5 го изземa само **§1**. §2 (што смее да се запише во DOM),
§3 (авторски markup), §4 (настаните се границата) и §5 (`destroy()`) **важат непроменето**. ln-http ги
поминува §2 и §3 тривијално (нула DOM записи — проверено), а паѓа по §4 и §5.

Една дополнителна забелешка: П5 ја именува категоријата како *„`ln-core` модулски помошници"*. ln-http
не е во `ln-core`, но ја задоволува вистинската мерка на П5 (нема host). Ако категоријата се сфати буквално
по патека наместо по мерка, ln-http паѓа во празнина. Тоа е доктринарна формулација, не наод против кодот —
запишано подолу во §Затечена состојба.

## Вердикт

Најтешкото е дека **ln-http ја преземa транспортната одлука од конекторот, глобално, без опт-ин**
(`src/ln-http.js:108`): го заменува `window.fetch` и ѝ ја заменува `signal`-от на секоја туѓа фетч-повик
(`:93`). §4 го поставува транспортот кај конекторот/координаторот (`_doctrine.md:130`); ln-http наместо да
биде транспорт, го пресретнува туѓиот — и притоа ја поништува свесната одлука на `ln-api-connector` да
дедуплицира по `targetEl`, не по URL (`ln-api-connector/src/ln-api-connector.js:112`). Второ, `cancelAll()`
(`:208`) стигнува и до мутациски барања, а `AbortError` нема `.status`, па сите три гранки на
`ln-data-coordinator.js:646-648` се лажни — откажаната мутација се класифицира како трајна грешка.
Трето, двата влезни настани (`:185`, `:186`) не го држат `:request-{action}` обликот што го држат другите 56
во библиотеката. Doc-drift е мал но реален: README го покажува компилираниот бандл како извор (`README.md:99`)
и целосно го премолчува `src/http-core.js`.

## Што е добро

Ова е чист, дисциплиниран фајл — повеќето замки на асинхрон код се избегнати намерно, не случајно.

- **Нула DOM записи.** `grep -n "\.style\.\|classList\|setAttribute\|innerHTML\|textContent\|createElement\|querySelector"`
  врз `src/*.js` → **ништо**. §2 и §3 се поминати без дискусија. Нема зашиен кориснички текст што стигнува до UI —
  единствената англиска низа во фајлот е `src/ln-http.js:107`, која никогаш не влегува во DOM.
- **Чист логички слој.** `src/http-core.js` — 51 линии, четири чисти функции, `grep "document\|window\|localStorage"` → **ништо**.
  Точно она што §0 (`_doctrine.md:17`) го бара од слојот „Логика".
- **Идентитетска проверка при чистење** — `src/ln-http.js:103`, `:153`, `:164`. Постар повик што доцна се
  завршува не го брише посвежиот запис од мапата. Ова е точно оној баг што вакви модули обично го имаат.
- **`body` се проследува со `!== undefined`** (`src/ln-http.js:143`), па намерно паѓачки тела (`0`, `''`, `false`)
  стигнуваат до серверот.
- **Слушачот на туѓиот `AbortSignal` се симнува во сите три гранки** — `:99-101` (Path A `finally`),
  `:150-152` (Path B resolve), `:161-163` (Path B reject). Нема висечки `abort` слушач на консументски signal.
- **Тивок `AbortError`** (`:165`) — откажаното не се пријавува како грешка кај консументот.
- **Нема `:destroyed` настан** — П2 (`_doctrine.md:142`) е задоволена без да се допира ништо.
- **Празна schema што ја кажува вистината** (`ln-http.schema.json:5`), наместо измислени атрибути.
- **Нема SCSS, и тоа е исправно** — нема DOM договор што би се изнудувал во dev, па `ln-http-dev.scss` би бил
  празна церемонија.

## Наоди

### 🟠 T1 — Транспортот на туѓи компоненти се преземa глобално, без опт-ин

**Каде:** `src/ln-http.js:59`, `:73-76`, `:93`, `:108` · `ln-api-connector/src/ln-api-connector.js:112-123`

`src/ln-http.js:108` го заменува `window.fetch` со `_wrappedFetch`. Секој фетч во страницата — библиотечен,
консументски, туѓ (analytics, A/B SDK) — оди низ `:73-76`:

```js
if (isIdempotentMethod(method) && _inflight.has(key)) {
	_inflight.get(key).abort();
	_inflight.delete(key);
}
```

и низ `:93`, каде авторската `options.signal` се заменува со композитен signal на ln-http.

§4 (`_doctrine.md:130`) вели: *„Рендерер никогаш не вика `fetch`. Транспортот е на конектор/координатор."*
Тоа е правило за **сместување** на транспортот. ln-http не се сместува во тој слој — тој го пресретнува.

**Достижна последица, докажана:** `ln-api-connector` има сопствен слој за откажување, и тој дедуплицира по
**елемент-цел**, не по URL:

```
ln-api-connector.js:112   const key = targetEl || 'sync';
ln-api-connector.js:113-115   if (self._inflight.has(key)) { self._inflight.get(key).abort(); }
ln-api-connector.js:119-123   return window.fetch(url, { method: 'GET', …, signal: controller.signal })
```

Тоа е свесна одлука: **два различни презентери смеат истовремено да го повлечат истиот URL**, затоа што имаат
различен `targetEl`. ln-http ја поништува таа одлука — двата повика имаат ист клуч `"GET <url>"`, па првиот се
прекинува. Конекторот не увезува ln-http, не знае за него, и нема како да се исклучи.

Забелешка за симетрија: ln-http **не** е изворот на асиметријата со `err.status`. `grep -n "\.status"` врз
`components/ln-http/src/*.js` враќа **само** `:156` (`status: response.status`) — ln-http никогаш не пишува
`err.status`. Асиметријата потекнува од конекторите: `ln-api-connector.js:17` ја поставува на секоја фрлена
грешка, `ln-couchdb-connector.js:160` само на 409. ln-http сепак **додава трета класа грешка без `.status`** —
види T2.

### 🟠 T2 — `cancel()` / `cancelAll()` стигнуваат до мутации, а `AbortError` нема `.status`

**Каде:** `src/ln-http.js:95`, `:191-201`, `:208-213` · `ln-data-coordinator/src/ln-data-coordinator.js:646-648`

Дедупот е ограничен на GET/HEAD (`:73`), но **сместувањето во мапата не е**:

```
src/ln-http.js:95   _inflight.set(key, controller);
```

Оваа линија се извршува безусловно, за секој метод. Затоа `cancel(url)` (`:191-201`, совпаѓање по
`key.endsWith(' ' + url)` на `:194`) и `cancelAll()` (`:208-213`) прекинуваат и POST/PUT/DELETE.

`ln-api-connector` и `ln-couchdb-connector` ги праќаат сите мутации преку `window.fetch` — т.е. преку овој
wrapper. Прекинат fetch фрла `AbortError`, кој носи `name`, не `status`. Кај координаторот:

```
ln-data-coordinator.js:646   const isAuth = status === 401 || status === 419;
ln-data-coordinator.js:647   const isTransient = status === 0 || status >= 500;
ln-data-coordinator.js:648   const isConflict = status === 409 || status === 412;
```

сите три се лажни за `status === undefined`. Откажана мутација — нешто што по природа е **преодно** и треба
повторен обид — паѓа надвор од `isTransient` и се третира како траен отказ.

Патеката за `query` не е засегната: координаторот излегува порано на `ln-data-coordinator.js:640-641`, пред
овие гранки.

README го засилува недоразбирањето: `README.md:11` вели *„POST and unsafe methods are bypassed to preserve
intent"*. Во контекст тоа се однесува на дедупот и е точно, но чита како „POST-от воопшто не поминува низ
wrapper-от" — а поминува, му се заменува signal-от (`:93`) и е достижен за `cancelAll()`.

### 🟠 T3 — `ln-http:request`: `request` е употребен како `{action}`, а не именува дејство (§4.1)

**Каде:** `src/ln-http.js:185`, `:186`

```
src/ln-http.js:185   document.addEventListener('ln-http:request', _onRequest);
src/ln-http.js:186   document.addEventListener('ln-http:cancel', _onCancel);
```

§4.1 (пресуда 2026-09-12) дава **три** легитимни влезни форми: `:request-{action}`, `:set-{noun}` и исходен влез (`ack`, `nack`, `page-failed`, `resolve-create`). Од двата настани тука, само едниот останува наод.

**`:request` е наодот.** Проблемот не е отсуство на префикс туку што `{action}`
отсуствува целосно: зборот `request` е ставен на неговото место и не именува
никакво дејство. `ln-toast:enqueue` е гол, но е **вистински глагол** — се знае
што бара. `ln-http:request` не кажува ништо.
`grep -rhon "'ln-[a-z-]*:request[a-z-]*'" components/*/src/*.js` враќа 56 различни
имиња, од кои точно два се вакви: `ln-http:request` и `ln-fill:request`
(`ln-fill/src/ln-fill.js:65`). Ова важи без оглед на тоа како ќе се пресуди §8
виљушка 2 — таа виљушка е за адресирањето, не за тоа дали името именува дејство.

**`:cancel` се повлекува од овој наод во §8 виљушка 2 (б).** Претходната
верзија на аудитот го прогласуваше за пресудено отстапување, повикувајќи се на
`ln-api-connector/src/ln-api-connector.js:387` (`'ln-api-connector:request-cancel'`)
како „истата семантика со исправно име". Таа споредба не држи: конекторскиот
слушач е врзан за host (`self.dom`), а овој е модулен на `document`. Тоа се
**различни начини на адресирање**, не двоен правопис на еден чин. Дали
компонента без host смее да носи гол глагол е отворено прашање и не се
пресудува тука.

**Последица:** консументот што го научил обликот од кој било друг компонент ќе испрати
`ln-http:request-cancel` и ништо нема да се случи — `_onCancel` (`:174`) слуша само на точното име и нема
fallback. Ова важи и додека (б) е отворена: каква и да биде пресудата, тивкиот
неуспех останува. Се бележи како последица, не како засебен наод.

Двата `document`-слушачи **сами по себе не се наод**. §4 (`_doctrine.md:131-132`) го дозволува тоа кога е
„самата природа на компонентата" — ln-http нема host, па нема друг јазол на кој би слушал.

### 🟠 T4 — `destroy()` не го враќа изворниот `fetch`, туку врзана копија

**Каде:** `src/ln-http.js:59`, `:229`

```
src/ln-http.js:59    const _origFetch = window.fetch.bind(window);
src/ln-http.js:229   window.fetch = _origFetch;
```

`_origFetch` **не е** изворниот `window.fetch` — тоа е нов, врзан функциски објект создаден од ln-http.
`destroy()` не го враќа изворниот; го инсталира тој нов.

§5 (`_doctrine.md:138`) бара `destroy()` да симне „сè што направила", а П3 (`_doctrine.md:144`) го дава тестот:
*„дали ова ќе постоеше ако компонентата никогаш не се извршеше?"* Врзаната копија не би постоела.

**Достижна последица, преку документираниот случај на употреба.** `src/ln-http.js:51` вели дека `destroy()` е
за *„dev hot-reload and tests"* — значи циклусот load → destroy → load се очекува да се повтори. Во вториот
циклус `:59` повторно бинда, овојпат врз веќе врзаната копија. По N топли превчитувања `window.fetch` е N
вгнездени bound функции. Плус, `window.fetch === ` изворната нативна референца е трајно лажна по првиот
`destroy()`.

Функционално повикувањето останува исправно — тоа е причината зошто ова е 🟠, а не 🔴. Но `README.md:67`
(*„restores native `fetch`"*) и `README.md:121` (*„restore `window.fetch = _origFetch`"*) го опишуваат како
целосно враќање, а не е.

## Затечена состојба — без пресуда

**BEM компаунди (§8.1).** ln-http **не ја допира** — нема SCSS, нема ниту една класа во JS. Нема што да се пријави.

**Формулација на П5 — каде спаѓа компонента без host што не е во `ln-core`.**
П5 (`_doctrine.md:74`, повторено на `:310-315`) ја именува категоријата *„`ln-core` модулски помошници"* и ја
образложува со *„немаат host елемент; нема јазол што би носел атрибут"*. Образложението е мерка (нема host),
насловот е патека (`ln-core`). ln-http ја задоволува мерката но не и патеката: сопствена папка во
`components/`, сопствен README и `schema.json`, нула host. `window.lnRouter` е втор таков случај.

Ова го пријавувам како затечена состојба зашто е формулација на доктрината, а не отстапување на кодот, и
аудиторот не пресудува. За овој аудит ја земав **мерката**, не патеката — §1 неприменлива, §2/§3/§4/§5 важат.
Ако чекор 4 реши поинаку, T3 и T4 остануваат непроменети (тие се §4 и §5), а делот „Каде живее" се менува.

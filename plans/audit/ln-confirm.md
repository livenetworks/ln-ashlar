# Аудит — ln-confirm

2026-09-11 · Опсег: `src/ln-confirm.js` (161), `README.md` (165), schema · Итерација 18/50

## Вердикт

Три режима, сите три документирани, и READMEто ги објаснува одлуките со причина —
вклучувајќи зошто состојбата се снима еднаш. Наодите: наследниот текстуален режим
трајно ја уништува иконата на копче со икона **и** текст, а машинеријата за
двоклик е мртов код што README-то изречно го демантира.

## Што е добро

**Го користи `shouldIgnoreClick` од `ln-core`** (`:39`) наместо да го препишува.
Тоа е еден од само двата вистински консумента на тој примитив — спротивно од
`ln-popover` PO2, кое го препиша послабо.

**`_getTimeout` е напишан правилно** (`:11-14`):

```js
const val = parseFloat(dom.getAttribute(TIMEOUT_ATTR));
return (isNaN(val) || val <= 0) ? DEFAULT_TIMEOUT : val;
```

`isNaN` и `<= 0` се проверени изречно, наместо `|| DEFAULT` идиомот што
`ln-toast` TS4 и `ln-circular-progress` CP1 го носат.

**Двоелементниот режим користи нативен `hidden` атрибут** (`:68`, `:112-113`), не
класа. Тоа е точно она што пресудата за core/theme поделбата го бара — и е
единствената компонента досега што крие на тој начин наместо преку `.hidden`
(SYS-7).

**Снимката при конструкција е документирана со причина**, не само пријавена
(README:134):

> re-reading per confirm would race AJAX-driven content updates and change the
> button text mid-confirm

А исклучокот е доследен: `_startTimer` го чита `data-ln-confirm-timeout` **свежо**
на секое вооружување (`:100`), и README-то го кажува тоа одделно.

**Иконскиот режим ја решава пристапноста затоа што знае дека CSS балонот е невидлив
за AT** (README:146). `:83-85` пишува `aria-label` + `aria-live`, а `_reset`
(`:130-142`) ги враќа симетрично, вклучувајќи го случајот кога оригиналот бил
отсутен → `removeAttribute`.

**Иконската размена е координирана со `ln-icon`, не импровизирана.** `:81` го менува
`<use href>` во `#ln-icon-check`; `ln-icon` README-то изречно го наведува
`ln-confirm` како еден од трите инјектори што минуваат низ истиот scan/fetch тек.

## Наоди

### 🟠 C1 — Наследниот текстуален режим трајно ја уништува иконата

**Каде:** `:33`, `:87`, `:125`

Изборот на режим (`:27`, `:78`) дава три патеки:

| маркап | `originalText` | режим | што се случува |
|---|---|---|---|
| `<button data-ln-confirm>Delete</button>` | `"Delete"` | наследен текст | `textContent` размена ✅ |
| `<button data-ln-confirm><svg/></button>` | `""` | иконски | `<use href>` размена ✅ |
| `<button data-ln-confirm><svg/>Delete</button>` | `"Delete"` | **наследен текст** | ❌ |
| со `[data-ln-confirm-idle]` / `-active` | — | двоелементен | `hidden` тогл ✅ |

Третиот ред е обичното копче со икона **и** етикета. `originalText` е `"Delete"`
(SVG не придонесува текст), значи `isIconButton` останува лажно и се оди на:

```js
this.dom.textContent = this.confirmText;    // :87 — бриши ги сите деца
…
this.dom.textContent = this.originalText;   // :125 — врати САМО текст
```

`textContent =` ги брише сите деца-јазли. При враќање се запишува само стрингот —
**`<svg>` никогаш не се враќа**. По еден циклус на потврда копчето е трајно без
икона.

README §Modes ги опишува трите режима доволно точно за внимателен читател да го
изведе тоа, и препорачува Two-Element „for rich content" (README:33, :140). Но
конкретната комбинација икона+текст никаде не е именувана како случај што губи DOM,
а тоа е најчестиот облик на копче во вистински интерфејс.

### 🟠 C2 — `_submitted` е мртов гард; README-то ја демантира заштитата што ја имитира

**Каде:** `:22`, `:46-47`, `:107`

```js
} else {
    if (self._submitted) return;      // :46
    self._submitted = true;           // :47
    e.stopPropagation();
    self._reset();                    // :52 → _reset() поставува _submitted = false (:107)
}
```

`_reset()` е последната работа во гранката и **секогаш** го враќа `_submitted` на
`false` пред обработувачот да заврши. Значи условот на `:46` никогаш не може да биде
точен при влез: полето е `false` при конструкција и `false` по секој премин.

Полето постои, се пишува, се чита — и не влијае на ниту едно однесување.

Целта била очигледно заштита од двоклик. README §Common Pitfalls изречно вели дека
таа заштита **не постои**:

> **Double-Click Protection:** Once the second click executes the target action, the
> button returns to idle. If your custom AJAX handler takes time, the user can click
> again and execute duplicate actions. Disable the button on submit.

Значи документацијата е точна за однесувањето, а кодот носи механизам што изгледа
како да го обезбедува спротивното. DOCTRINE §2 („Definition of Done" — функција
постои само ако денес ја вика школката) го покрива овој случај.

### 🟠 C3 — Зашиен англиски `'Confirm?'` станува видлив текст и `aria-label`

**Каде:** `:34`

```js
this.confirmText = dom.getAttribute(DOM_SELECTOR) || 'Confirm?';
```

Стрингот се употребува на две места што корисникот ги перцепира:

- `:87` — `this.dom.textContent = this.confirmText` (видлива етикета)
- `:83-84` — `data-tooltip-text` и `aria-label` (CSS балон + говор на екрански читач)

DOCTRINE §4 бара нула зашиен кориснички текст во JS — сè од `<template>`,
`buildDict()` или `Intl`. README:60 го документира default-от, но документирано не
значи усогласено: во македонска апликација `<button data-ln-confirm>` покажува
`Confirm?`.

Тоа е истата класа како `ln-external-links` EL1 (`(opens in new tab)`) и
`ln-core` R6 (македонскиот речник) — библиотеката има три различни начини да
испорача зашиен јазик.

Дополнително, `||` (SYS-2) значи дека и `data-ln-confirm=""` дава `'Confirm?'` —
што README-то го тврди како намерно, па тука е споредно.

### 🟡 C4 — Две атрибути што библиотеката ги пишува живеат надвор од `data-ln-*`

**Каде:** `:62`, `:83`, `:109`, `:121`

| атрибут | пишува | чита |
|---|---|---|
| `data-confirming` | `:62` / брише `:109` | `theme/components/_confirm.scss` CSS хук |
| `data-tooltip-text` | `:83` / брише `:121` | `theme/config/mixins/_confirm.scss:23` — `content: attr(data-tooltip-text)` |

Обете се документирани (README:62-63) како „Managed state … public CSS hook", значи
се намерни. Забелешката е дека се **голи `data-*`**, надвор од `data-ln-*` просторот
што сите други компоненти го користат за состојба.

Практична последица: `scripts/sync-ln-schemas.mjs` скенира само `data-ln-*`, па
овие два атрибути се невидливи за schema-та и за CI docs портата. Договорот што
README-то го објавува не е покриен од автоматската проверка што ги покрива сите
други.

Плус: `data-tooltip-text` е паралелен механизам на `ln-tooltip`, кој постои и го
користи `data-ln-tooltip`. Две имплементации на балон-текст во иста библиотека.

## Затечена состојба

Снимката при конструкција (`originalText`, `confirmText` на `:33-34`) е свесна
одлука со запишана причина, не пропуст од `defineAttrs` миграцијата — тоа е првиот
случај досега каде „парсирано еднаш" е **аргументирано**, не наследено.

`data-ln-confirm-timeout` пак се чита свежо, што покажува дека поделбата е намерна.

Конзолен излез: нула.

# Аудит — ln-form

2026-09-11 · Опсег: `src/ln-form.js` (99), `README.md` (264), schema · Итерација 20/50

## Вердикт

99 линии што ја почитуваат најтврдата пресуда во репото — формата не слуша `submit`
и не серијализира ништо. Наодите се и двата на границата: README-то ја документира
како своја една опција што ја имплементираат други две компоненти, а скриениот
`_method` input што компонентата го создава никогаш не се чисти.

## Што е добро

**Не слуша `submit`. Воопшто.** `data-flow.md §4.5` бара точно тоа, и е испочитувано
буквално: единствените слушачи се `ln-fill` (`:37`) и `reset` (`:38`), а увозот
(`:1`) зема само `populateForm`, `dispatch`, `registerComponent` — **не**
`serializeForm`. README:6-7 го повторува како прв принцип. Ова е компонента чија
најголема вредност е она што не го прави.

**Гардот за вгнездени fillable-и** (`:22`):

```js
if (e.target !== self.dom) return;
```

`lnFill` фан-аутот испраќа на секој `[data-ln-form], [data-ln-fillable]`, а настанот
буклае. Без овој ред, `[data-ln-fillable]` внатре во формата би ја натерал формата да
се пополни втор пат со истиот запис.

**Null запис = нативен `reset()`, не втора гранка** (`:26-30`). Наместо да пишува
паралелна логика за „нов" режим, компонентата вика `form.reset()`, а нативниот
`reset` настан потоа го активира `_onReset` (`:33-35`) што го враќа основното
`action`. Еден пат, две однесувања — и коментарот ја кажува врската.

**Синтетичките настани се поделени правилно** (`:49-53`): `SELECT`/checkbox/radio →
`change`, сè друго → `input`. Тоа е она што ги буди `ln-validate`, `ln-autoresize` и
`ln-slug` — и токму она што `ln-slug` README-то го тврди дека се случува.

**`_baseAction` се снима при конструкција** (`:15`), па враќањето од edit во create
режим е точно, а не претпоставено.

**`encodeURIComponent(id)`** и во двата пата (`:77`, `:79`).

## Наоди

### 🟠 F1 — README ја документира како своја опција што ја имплементираат други

**Каде:** `README.md:68`, во табелата **„### HTML Attributes"** на самата компонента

> `data-ln-form-scope` | `<form>` | Opt-in local-first write path. Empty = nearest
> ancestor `[data-ln-data-coordinator]`. … **Intercepts submit**; incompatible with
> native/ajax submit on the same form.

`src/ln-form.js` не го спомнува тој атрибут никаде. Ниту `ln-form.schema.json`
(декларира точно четири: `data-ln-debug`, `data-ln-form`, `-action-edit`,
`-action-method`).

Вистинските сопственици:

| фајл | улога |
|---|---|
| `ln-data-coordinator/src/ln-data-coordinator.js:9` | `const SCOPE_ATTR = 'data-ln-form-scope'` — го имплементира write патот |
| `ln-ajax/src/ln-ajax.js:6,52` | го чита за да се повлече: *„the ln-data-coordinator write pipeline takes precedence; skipping ajax interception"* |

Два одвоени проблема:

**(а) Договорот покажува погрешно.** Читател што ја отвора табелата на атрибути на
`ln-form` заклучува дека `ln-form` го поседува тоа однесување. Истата табела на два
реда погоре вели дека формата **не** слуша `submit`; редот подолу вели дека еден
нејзин атрибут „intercepts submit". Двете се точни само ако знаеш дека
пресретнувањето се случува во друга компонента — што README-то не го кажува.

**(б) Префиксот лаже за сопственоста.** Правилото е дека префиксот на атрибутот е
полното име на компонентата што го поседува. `data-ln-form-scope` носи
`data-ln-form-`, а сопственик е `ln-data-coordinator`. Затоа и заврши во погрешната
табела — README-от го следел името.

### 🟠 F2 — Скриениот `_method` input се создава и никогаш не се чисти

**Каде:** `:56-66` наспроти `:88-94`

`_ensureMethodInput` му додава на формата траен јазол:

```js
input = document.createElement('input');
input.type = 'hidden'; input.name = '_method'; input.value = '';
this.dom.appendChild(input);
```

`destroy()` (`:88-94`) ги симнува двата слушача и ја брише инстанцата — но **input-от
останува**, со која било вредност што ја имал.

Тоа не е само DOM отпад. `ln-core/helpers.js:425-429` (`resolveFormMethod`) го чита
токму тој јазол:

```js
const methodInput = form.querySelector('input[name="_method"]');
const raw = (methodInput && methodInput.value !== '') ? methodInput.value : form.method;
```

Значи форма уништена додека била во edit режим (`methodInput.value === 'PUT'`,
`:81`) го задржува тоа засекогаш: и `ln-data-coordinator`-овиот native-submit claim и
`ln-form`-овата submit порта потоа читаат **PUT** за форма што нема повеќе компонента
да ја врати во create режим.

**Достижност:** само преку рачен `destroy()` додека елементот останува во документот
— автоматскиот пат се пали за откачени елементи, каде не е важно. Ниска, но
последицата е тивка промена на HTTP глаголот.

## Затечена состојба

`_baseAction` е снимен еднаш (`:15`) — свесно, зашто е референтната точка за враќање.
Сите други вредности (`ACTION_EDIT_ATTR`, `ACTION_METHOD_ATTR`) се читаат **свежо** во
`_applyActionMode` (`:69`, `:75`, `:81`), што значи дека промена на тие атрибути по
init важи. Прва компонента во слој 3 што ја има таа поделба намерно.

Конзолен излез: нула.

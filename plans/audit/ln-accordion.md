## Што е добро

**Вгнездувањето е решено со DOM предок, не со книговодство.** Две
`closest('[data-ln-accordion]')` проверки — една за влезниот настан (`:15`), една
по кандидат во каскадата (`:19`) — и произволна длабочина работи без ниту едно
поле состојба. Компонентата нема поим дека постојат други акордеони.

**Нула кеширана состојба.** Нема листа тогли, нема покажувач кон активен панел,
нема DOM кеш. `querySelectorAll` се пушта по настан, а README-то ја кажува
причината (настанот е кориснички, еден по клик).

**Каскадата оди преку атрибут, не преку метод.** `:21` пишува
`data-ln-toggle='close'` и застанува таму — целиот close pipeline (cancelable
настан, класа, ARIA, persist) е одговорност на `ln-toggle`. Точно по CQS.

**`:destroyed` е документиран** во табелата на настани — за разлика од `ln-toggle`,
кое го испраќа истиот настан без да го наведе.

## Наоди

### 🟠 A1 — Нема Detail Guard на туѓ настан

`:15` — `if (e.detail.target.closest(...))` го дереференцира `e.detail` без
проверка. DOCTRINE §5 бара Detail Guard за слушачи на **надворешни** настани, а
`ln-toggle:open` доаѓа од друга компонента.

**Достижност:** ниска. `ln-toggle` секогаш испраќа `{ target: el }` преку
`dispatch()`, кој гарантира `detail = detail || {}`. Пука само на рачно испратен
`ln-toggle:open` без detail.

### 🟡 A2 — Табелата на настани тврди дека влезниот настан нема detail

README §Event lifecycle:

| Event | Direction | `detail` |
|---|---|---|
| `ln-toggle:open` | in (bubble) | **—** |

Но `:15` и `:18` го читаат токму `e.detail.target`. Табелата вели дека полето што
компонентата го користи не постои.

### 🟡 A3 — Погрешен број линии и погрешен изворен пат

- README §1: *„It contains only 38 lines of JavaScript"* — изворот е **41**.
- Internals: *„Source: `components/ln-accordion/ln-accordion.js`"* — тоа е
  **компајлираниот bundle**. Изворот е `src/ln-accordion.js`.
  (Истиот образец како `ln-toggle` T8 и `ln-autoresize` — веројатно системски.)

### 🔵 A4 — `:destroyed` се испраќа пред бришењето, кај `ln-toggle` после

`ln-accordion.js:34-35` — прво `dispatch`, потоа `delete`.
`ln-toggle.js:121-124` — прво `delete`, потоа `dispatch`.
Ист животен настан, спротивен редослед во две компоненти. Плус истиот проблем со
достижност: `destroy()` го вика `ln-core` само за откачен јазол, па буклачкиот
настан не стигнува никаде.

### 🔵 A5 — Не ги користи `ln-toggle:request-*` настаните

`ln-toggle` слуша `request-close` (`ln-toggle.js:76`), но акордеонот пишува атрибут
наместо да го испрати. Двата пата се валидни; вториот никогаш не се користи од
единствената компонента што би можела. Врзано со `ln-toggle` T6.

# Аудит — ln-time

2026-09-11 · Опсег: `src/ln-time.js` (199), `src/time-model.js` (64), `README.md` (95), schema · Итерација 24/50

## Вердикт

Кодот е меѓу најчистите во библиотеката — доктрината го именува како референтна
имплементација за **три** обрасци. README-то е меѓу најнеточните: две од трите
„Common Pitfalls" се фактички погрешни, а шест од седум редови во табелата со
релативни прагови покажуваат излез што компонентата не го произведува.

## Што е добро

**Доктрината го цитира како еталон, трипати.** `component-guide.md:187`
(*„Shared Interval (ln-time pattern)"*), `:239` (*„Formatter Cache (ln-time
pattern)"*) и `:343` (*„Title attribute for hover context (ln-time)"*). Ниту една
друга компонента не е именувана толку пати како извор на образец.

**Споделениот интервал е единствениот точен пример за self-purging пул.**
`_tickRelative` (`:49-58`) ја брише секоја инстанца чиј `dom` веќе не е под
`document.body` — значи елемент отстранет преку `innerHTML = ''` без `destroy()`
не го држи тајмерот жив. `component-guide.md:236` изречно ја кажува причината зошто
е `Set`, не `WeakSet`: *„because we need to iterate — but we clean up manually"*.

**Нула настани, нула конзолен излез, нула `createElement`, нула inline стил,
нула зашиен англиски текст.** Ниту еден друг рендерер во библиотеката нема сите пет
истовремено. Компонентата не измислила API што никој не го бара — нема
`ln-time:rendered`, нема `ln-time:before-format`.

**`this.dom = dom` е првиот исказ во конструкторот** (`:138`). Нема bail-гранка пред
доделувањето, па SYS-1 (`destroy()` фрла на bail-создадена инстанца) не важи овде.

**Кешот на форматери е клучиран и по локале и по опции** (`:19`) — што значи дека
`short` режимот, кој ги менува опциите зависно од годината (`time-model.js:58-60`),
добива посебен запис наместо да враќа погрешно кеширан форматер. Доктринарниот
пример на `component-guide.md:247` го **нема** тој случај; изворот е поточен од
документот што го цитира.

**`fallback && fallback.monthsLong` гардот** (`:67`, `:85`) значи дека кога
`registerLocaleFallback` ќе биде пребришан со празен `{}` — точно она што
`ln-date` DT2 го прави при второ поле за датум — `ln-time` тивко се враќа на
нативниот `Intl` наместо да фрли. Ненамерна отпорност, но вистинска.

**`time-model.js` е чист и жив.** Нула `window`/`document`/`localStorage`, обата
извоза увезени (`:2`) и повикани (`:64`, `:79`, `:95`, `:99`, `:103`). Плус
`now` е инјектибилен параметар (`calculateRelativeTime(date, now = Date.now())`) —
единствениот модел досега напишан за тестирање без замрзнување на часовникот.

**`ln-time-dev.scss` ги фаќа обата авторски промашувања** — `data-ln-time` на
не-`<time>` елемент, и `<time data-ln-time>` без `datetime`. CSS афорданс, како
што `mindset.md:133` бара.

## Наоди

### 🔴 T1 — `datetime="0"` дава 1 јануари **2000**, а негативен печат дава година 86399

**Каде:** `ln-core/date.js:14` низ `src/ln-time.js:115`

`parseDateInput` ја има портата `if (!isNaN(num) && num > 0)`. За `0` и за секој
негативен број таа порта **не пропушта** — но функцијата не враќа `null`. Паѓа на
стринг-гранката (`date.js:21-26`), каде `new Date(str)` го парсира сировиот стринг
како датумска низа:

```
"0"        → 1999-12-31T23:00:00.000Z    (V8 го чита „0" како година 2000)
"00"       → 1999-12-31T23:00:00.000Z
" 0 "      → 1999-12-31T23:00:00.000Z
"-86400"   → +086399-12-31T23:00:00.000Z
```

(Проверено со `node -e` врз точната гранка на `parseDateInput`.)

Значи проблемот **не е** дека пре-1970 датумите се отфрлаат — тие се **тивко
погрешно парсираат**. `<time data-ln-time="full" datetime="0">` не го задржува
серверскиот fallback текст; тој се пребришува со **1 јануари 2000**. А датум на
раѓање пред 1970 (`datetime="-1234567890"`, 1930-11-18) се рендерира како година
некаде во 86-тиот милениум.

**Достижност:** `demo/admin/src/pages/time.html:178` веќе го содржи точно тој
случај — `<time data-ln-time="full" datetime="0">epoch</time>` — во табела насловена
како рабни случаи. Значи сценариото не е хипотетичко; веќе е во репото како
демонстрација, а прикажува погрешна година. Второто множество (негативни печати) е
секоја апликација што прикажува датуми на раѓање.

Ова е достижниот крај на `ln-core` R2. Овде се затвора за `ln-time`; истата порта
го погодува и `ln-date` (DT6, 13 повикувања).

### 🟠 T2 — Две од трите „Common Pitfalls" се фактички неточни

**Каде:** `README.md:79-81` наспроти `ln-core/date.js:6-29`

> **Using ISO Strings:** `datetime="2025-01-15T14:30:00Z"` is not parsed. The
> component skips non-numeric values, leaving the original fallback text.

Неточно. `parseDateInput` има изречна стринг-гранка (`date.js:21-26`) што прави
`new Date(str)`. Проверено:

```
"2025-01-15T14:30:00Z"  → 2025-01-15T14:30:00.000Z   ✅ парсирано
"2025-01-15"            → 2025-01-15T00:00:00.000Z   ✅ парсирано
```

`ln-core/README.md:955` го тврди истото што и кодот:
*„Parses Date objects, **ISO strings** (`YYYY-MM-DD` or `YYYY-MM-DDTHH:mm:ssZ`),
and Unix seconds/milliseconds timestamps"*.

> **Passing Millisecond Timestamps:** … Divide milliseconds by `1000` before rendering.

Исто неточно. `date.js:16` е токму таа нормализација:
`const ms = num < 1e11 ? num * 1000 : num`. Проверено:
`"1736952600000"` → `2025-01-15T14:50:00.000Z`, идентично со секундната форма.

Само третиот pitfall (празен `datetime`) е точен (`:113`).

Истата неточност се повторува во договорната табела на `README.md:48`:

> `datetime` | `<time>` | **Required**. Unix timestamp in **seconds** (not milliseconds).

Тоа е лажно **стеснување** на договорот. `<time datetime="2025-01-15">` е формата
што HTML спецификацијата ја пропишува за тој елемент; README-то на консументот му
кажува дека таа форма не работи и го праќа да конвертира во Unix секунди без
причина. Огледален случај на SYS-19 — README тврди **ограничување** што не постои.

### 🟠 T3 — Секој пример за релативен излез е од погрешен `style`

**Каде:** `README.md:55` и `:65-73` наспроти `src/ln-time.js:29`

Кодот гради `new Intl.RelativeTimeFormat(locale, { numeric: 'auto', style: 'narrow' })`.
README-то ги наведува излезите на `style: 'short'`.

| праг | README вели | кодот дава |
|---|---|---|
| `< 10s` | `"now"` | `now` ✅ |
| `< 60s` | `"45 sec. ago"` | `45s ago` |
| `< 60min` | `"5 min. ago"` | `5m ago` |
| `< 24h` | `"3 hr. ago"` | `3h ago` |
| `< 7d` | `"2 days ago"` | `2d ago` |
| `< 30d` | `"2 wk. ago"` | `2w ago` |
| Format Modes `:55` | `"3 hr. ago"`, `"in 2 hr."` | `3h ago`, `in 2h` |

(Проверено со `Intl.RelativeTimeFormat` во Node за обата стила.)

Шест од седум редови се погрешни. Тоа не е козметика — `narrow` наспроти `short` е
видлива разлика во ширина на колона, и е токму она што авторот го чита кога
проценува дали релативниот режим му се вклопува во табела.

### 🟠 T4 — Зашиен македонски предлог во генеричката fallback патека

**Каде:** `:73`

```js
return `${day} ${month} ${year} во ${hours}:${mins}`;
```

`DOCTRINE.md:73`:

> **Zero Display Text in JS:** Hardcoded UI text/labels in JS are strictly
> forbidden. Translatable text lives in `<ul hidden><li data-{component}-dict="key">`
> … or relies on browser `Intl` APIs.

`DOCTRINE.md:74` го носи единствениот исклучок — **симболи на мерни единици**
(`'KB'`, `'ms'`). Предлог во реченица не е мерна единица.

Проблемот не е што зборот е македонски, туку што е во **јазично-неутрална** гранка.
`_formatFull` ја зема таа патека за **кој било** регистриран резервен речник:

```js
const fallback = getLocaleFallback(locale);
if (fallback && resolvedLocale !== langPrefix && fallback.monthsLong) { … }
```

`registerLocaleFallback` е јавен API (`window.lnCore.registerLocaleFallback`,
`helpers.js:1033`), и постои токму за јазици што `Intl` не ги знае. Консумент што
регистрира речник за таков јазик го добива својот месец, но со **македонски
предлог** и **македонски редослед** `ден месец година` внатре во својот стринг.

Заедно со тоа: часот е тврдо 24-часовен `HH:mm` (`:71-72`), без оглед на
конвенцијата на јазикот.

**Достижност:** модерниот `Intl` го резолвира `mk` нативно (проверено:
`resolvedOptions().locale === 'mk'`), па за македонски гранката е мртва. Живее за
(а) енџини без `mk` податоци — SSR со small-icu Node, стар Android WebView; и
(б) секој консументски речник за јазик што `Intl` не го поддржува, што е целата
намена на механизмот.

Четврто појавување на SYS-13 — прво што не е англиски.

### 🟡 T5 — `title` се пишува, не е документиран, и преживува `destroy()`

**Каде:** `:131-133` наспроти `:162-169`

```js
if (mode !== 'full') {
    instance.dom.title = _formatFull(date, locale);
}
```

Механизмот е доктринарно санкциониран — `component-guide.md:343` го наведува
буквално како *„Title attribute for hover context (ln-time)"*. Три забелешки:

1. **README не го спомнува ниту еднаш.** Grep за `title` низ `README.md` враќа нула.
   Значи единственото место каде авторот може да дознае дека компонентата пишува
   `title` е доктринарен документ за пишување компоненти, не договорот на
   компонентата.
2. **Го пребришува авторскиот `title`.** `<time data-ln-time="short" datetime="…"
   title="Внесено од Ана">` го губи тој текст при првиот рендер, без предупредување.
3. **`destroy()` не го враќа.** Уништената инстанца остава `title` со форматиран
   датум на елемент што повеќе нема компонента да го ажурира. SYS-9.

### 🟡 T6 — README Internals покажува на компајлираниот bundle и наведува погрешен `extraAttributes`

**Каде:** `README.md:87`

> Source: `components/ln-time/ln-time.js`. Registers via `ln-core`'s
> `registerComponent` with `extraAttributes: ['datetime']`

Две работи:

- **`components/ln-time/ln-time.js` е build артефакт** (15 035 бајти, минифициран).
  Рачно пишаниот извор е `src/ln-time.js`. Шесто појавување на SYS-3.
- **`extraAttributes` не е `['datetime']`.** Изворот (`:195`) декларира три:
  `['datetime', 'data-ln-time-locale', 'lang']`. Не е ситница — `data-ln-time-locale`
  во таа листа е причината зошто менувањето на локалето по-елемент воопшто
  пререндерира, а тоа е документирана функција (`README.md:49`).

### 🟡 T7 — Невалиден `datetime` по првиот рендер остава застарен текст

**Каде:** `:112-117` наспроти `README.md:81`

```js
const raw = instance.dom.getAttribute('datetime');
if (!raw) return;
const date = parseDateInput(raw);
if (!date) return;
```

Раниот излез го чува `textContent`. README-то ја објаснува таа одлука само за
почетната состојба:

> **Empty `datetime` Attributes:** … the component will skip formatting to
> **preserve server fallback strings**.

Но `README.md:14` (Philosophy #4) реактивноста ја продава како прворедна функција:
*„Changing `datetime` or `data-ln-time` triggers automatic DOM re-renders"*. По
првиот рендер серверскиот fallback е веќе избришан, па
`el.setAttribute('datetime', '')` не открива fallback — го **замрзнува претходно
форматираниот датум**, кој сега е неповрзан со атрибутот. Истото важи за
`datetime="0"` (види T1) и за секој невалиден внес.

Значи една иста линија значи „зачувај го серверскиот текст" при init и „задржи го
претходниот резултат" при реакција. README-то ја опишува само првата.

## Затечена состојба

**Доктрината го учи `ln-time` со `effects`; изворот сè уште е на наследната патека.**
`component-guide.md:150-153` дава буквален пример:

```javascript
registerComponent(DOM_SELECTOR, DOM_ATTRIBUTE, _component, 'ln-time', {
    effects: {
        'datetime': function (dom) { _render(dom[DOM_ATTRIBUTE]) },
        'data-ln-time': function (dom) { _render(dom[DOM_ATTRIBUTE]) }
    }
})
```

`src/ln-time.js:194-198` користи `extraAttributes` + `onAttributeChange` — гранка (C),
означена во `helpers.js:776` како *„legacy path"*. Водичот дури изречно вели
*„No attribute list to maintain"*, додека компонентата што ја именува одржува листа
од три. Тоа е инверзијата на атрибутната реактивност на пас 1, не наод против
компонентата.

**Водичот му припишува `console.warn` повици што ги нема.** `component-guide.md:114`,
`:424` и `:434` ги наведуваат `console.warn('[ln-time] Missing datetime')` и
`console.warn('[ln-time] Init called with null element')` како стандардни. Изворот
има **нула** конзолни повици; дијагностиката е во `ln-time-dev.scss`, што е
патеката на `mindset.md:133`. Значи `ln-time` ја реши суспендираната виљушка #1
во корист на `mindset.md`, а `component-guide.md` сè уште го користи неговото име за
спротивниот образец.

**`registerLocaleFallback` / `getLocaleFallback` не се документирани никаде.** Grep
низ `components/ln-core/README.md` враќа нула. `ln-time` **консумира** речник
(`{ monthsLong, monthsShort }`) што никогаш не го регистрира — единствениот
регистратор во библиотеката е `ln-date` (`ln-date.js:110`) плус вградениот `mk` во
`helpers.js:1012`. Значи македонскиот излез на `ln-time` зависи од тоа дали
`ln-date` е на страницата и што регистрирал, а обликот на речникот е неформален
договор меѓу три фајла без ниту еден ред документација.

Конзолен излез: нула. Настани: нула. `createElement`: нула. Inline стил: нула.

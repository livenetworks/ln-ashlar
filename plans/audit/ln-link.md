## Вердикт

README од 341 линија за извор од 212 — најчесно документираната компонента во кампањата,
која сама ги именува своите отстапувања вклучувајќи го и тоа дека статусната лента
никогаш не се уништува — но која при вчитување качува `<div>` во `document.body` без ниту
еден консумент, и која shift-клик тивко го претвора во обична навигација во истиот таб.

## Што е добро

**README-то ги пријавува сопствените отстапувања, пред ревизорот да ги најде.**

| линија | признание |
|---|---|
| `:311` | *„`_statusEl` — module-level … appended to `document.body` once, at first init. **Never destroyed**, even if all…"* |
| `:341` | *„Assigns `window.lnLink = { init, destroy }` directly **rather than the shared `registerComponent` helper** used by newer components"* |
| `:199-200` | *„**Does not fire `ln-link:navigate` on the modifier-key path.** Ctrl/Cmd+click and middle-click call `window.open` directly"* |

Три отстапувања што во други компоненти беа наоди, тука се документирани пред да бидат
прашани. Тоа ја менува природата на овој аудит: наодите подолу се против **одлуките**, не
против документацијата.

**Бespoke животниот циклус е во санкционираната форма.** `component-guide.md:176-179`
дозволува компонента со сопствен `childList` циклус да користи `observeAttributes` за
атрибутната половина. Проверено — точно **три** компоненти имаат сопствен
`MutationObserver` и нула `registerComponent`: `ln-ajax`, `ln-external-links`, `ln-link`.
Бројот во документот се совпаѓа, и сите три го користат `observeAttributes`. Не е наод.

**Синтетичкиот клик не влегува во циклус.** `:48` `link.click()` испраќа клик што
буклае назад до редот и повторно го буди `_handleClick` — но `:33`
(`e.target.closest('a, …')`) сега е вистинито, па излегува веднаш. Заштитата е
структурна, не преку знаменце.

**`mouseleave` слушачот е споделен, па се тргa коректно.** `_handleMouseLeave` (`:61`) е
модулна функција, не затворач — значи `removeEventListener` на `:91` ја погодува точно
истата референца. Двата per-row слушачи се чуваат како expando-и (`:75`, `:78`) токму
затоа што **се** затворачи, и README:313 го објаснува тоа.

**Уништувањето по атрибут е врзано.** `observeAttributes` (`:181-187`) — кога
`data-ln-link` ќе се тргне, `_destroyContainer` ги симнува сите редовни слушачи. Многу
компоненти во кампањата немаат таква патека воопшто.

**Схемата е минимална и точна.** Два записа, обата свои.

## Наоди

### 🟠 K1 — `<div>` се создава и се качува во `document.body` при вчитување, без консумент, и никогаш не се вади

**Каде:** `:13-17`, повикано од `_initializeAll:202`

```js
function _createStatusBar() {
	_statusEl = document.createElement('div');
	_statusEl.className = 'ln-link-status';
	document.body.appendChild(_statusEl);
}
```

**Извори на правилото — три, и трите се погодени:**

| правило | текст |
|---|---|
| `DOCTRINE.md:70` | *„Component DOM structures belong in `<template data-ln-template="…">` … **Never build DOM trees via `createElement` chains in JS**."* |
| `docs/architecture/mindset.md:25` | *„**JS never creates UI chrome.**"* |
| `CLAUDE.md` §1 | *„**No bare `<div>`**: Does every `<div>` have a structural class? Can a semantic element … be used instead?"* |

Третото е најдиректно: `<div class="ln-link-status">` е точно бар `<div>` со презентациска
класа, во компонента што има dev-SCSS фајл што проверува туѓ markup за структурни
пропусти.

**Инсталацијата е безусловна.** `_initializeAll` (`:201-205`) се извршува при
`DOMContentLoaded` или веднаш, и го вика `_createStatusBar()` **пред** `constructor(document.body)`
(`:204`). Значи страница со нула `[data-ln-link]` сепак добива дополнителен јазол во
`<body>`. Идентичен облик како `ln-nav` N1 — глобален спореден ефект при вчитување — само
што овде тоа е DOM јазол, не замена на API.

**Никогаш не се вади.** `window.lnLink.destroy` (`:199`) е `_destroyContainer`, кој работи
само со редови и контејнери (`:97-111`). Ниту таа функција ниту која било друга не го
допира `_statusEl`. README:311 го кажува тоа отворено.

**Санкционираниот образец постои и е применет во соседна компонента.** `ln-toast` држи
`<template>` во markup и клонира; `ln-confirm` има изречен *Micro-Component Exception* во
`DOCTRINE.md:71` за бихејвиорални декоратори на копчиња — што `ln-link` не е, зашто
создава **нов, независен, страничен** елемент, не преработува постоечко копче.

### 🟠 K2 — Shift-клик и Alt-клик тивко стануваат навигација во истиот таб

**Каде:** `:41-48`

```js
if (e.ctrlKey || e.metaKey || e.button === 1) {
	window.open(href, '_blank', 'noopener,noreferrer');
	return;
}

const before = dispatchCancelable(row, 'ln-link:navigate', { … });
if (before.defaultPrevented) return;
link.click();                                            // :48
```

`ln-core/helpers.js` `shouldIgnoreClick` ги проверува **четирите** модификатори плус
`button !== 0`:

```js
if (event.ctrlKey || event.metaKey || event.shiftKey || event.altKey) return true;
if (typeof event.button === 'number' && event.button !== 0) return true;
```

Овде `shiftKey` и `altKey` недостигаат. Последицата не е само „настанот не се испраќа" —
таа е **обратна од очекувањето на корисникот**:

1. Корисникот прави **shift-клик** врз редот, очекувајќи нов прозорец (стандардно
   однесување во секој прелистувач).
2. `:41` не фаќа → се оди на нормалната гранка.
3. `:48` `link.click()` испраќа **синтетички** `MouseEvent` преку `HTMLElement.click()`.
   Тој настан нема `shiftKey` — по спецификација, `click()` создава настан со сите
   модификатори на `false`.
4. Прелистувачот навигира **во истиот таб**, газејќи ја тековната страница.

Истото важи за alt-клик (стандардно: преземање или без дејство, зависно од платформата).

**SYS-18, седми случај** — и единствениот каде послабата копија дава активно погрешно
однесување, а не само пропуштен guard. Другите шест (`ln-popover`, `ln-external-links`,
`ln-tabs`, `ln-fill`, `ln-list`, `ln-table`, `ln-ui-coordinator`) само не го игнорираат
кликот; овде кликот се пренасочува.

**Достижност:** `demo/admin/src/pages/link.html` има три контејнери (`:9`, `:57`, `:87`),
секој со линкови. Shift-клик е достижен веднаш.

README:158 и `:199-200` ги наведуваат само *„Ctrl/Cmd+click and middle-click"* — значи и
документацијата ја носи истата дупка.

### 🟡 K3 — Единствениот глобал во библиотеката што не е конструктор

**Каде:** `:199`

```js
window[DOM_ATTRIBUTE] = { init: constructor, destroy: _destroyContainer };
```

Сите останати 49 компоненти го добиваат глобалот преку `registerComponent`, кој прави
`window[attribute] = constructor` (`ln-core/helpers.js:908`) — значи `window.lnToggle(el)`,
`window.lnSortable(el)`, `window.lnNav(el)` се **функции**. `window.lnLink(el)` **фрла**;
правилниот повик е `window.lnLink.init(el)`.

README го документира точно (`:183`, `:188`, `:341`), што значи дека авторот што го чита
овој README нема проблем. Проблемот е за авторот што го научил образецот од која било
друга компонента.

Забелешка: двојната заштита на `:7` (`window[DOM_ATTRIBUTE] !== undefined`) работи
подеднакво добро со објект како со функција, па таа половина е исправна.

### 🟡 K4 — Три документациски пропусти во инаку примерна README

**1. Пописот на увози е нецелосен, и го пропушта најважниот.** `:307`:

> *„Source: `components/ln-link/ln-link.js`. Imports `dispatchCancelable` and `guardBody`
> from `../ln-core`."*

Изворот увезува **три** (`:1`):

```js
import { dispatchCancelable, guardBody, observeAttributes } from '../../ln-core';
```

Испуштениот е `observeAttributes` — и токму тој е причината зошто bespoke циклусот на оваа
компонента е **санкциониран** (`component-guide.md:176-179`). Без него, сопствениот
`MutationObserver` би изгледал како отстапување; со него, е една од трите дозволени.
Internals секцијата го испушта единственото нешто што ја брани архитектурата.

**2. SYS-3.** `:307` — `components/ln-link/ln-link.js` е компајлираниот бандл (11.6 KB)
наместо `src/ln-link.js` (6.6 KB). **Петнаесетти** потврден случај.

Иронијата се повторува од `ln-nav`: `:294` во истата README покажува на **вистинскиот**
извор.

**3. SYS-20 — две `file:///` апсолутни машински патишта**, `:294` и `:295`. `ln-link` е
една од 16-те.

### 🟡 K5 — Уништувањето не ја крие статусната лента; нема `ln-link:destroyed`

`_destroyContainer` (`:97-111`) ги трга слушачите на сите редови и го брише
`lnLinkInit` знаменцето. Она што не го прави: `_hideStatus()`.

Значи уништување на контејнер **додека покажувачот е врз ред** го остава
`.ln-link-status--visible` запален, со последниот `href` во `textContent` — а
`mouseleave` слушачот што би го исчистил е веќе тргнат (`:91`). Лентата останува видлива
до следниот hover врз друг `[data-ln-link]` ред, или засекогаш ако таков нема.

**SYS-9**, со тоа што остатокот овде е **на туѓ елемент** (модулната лента), не на
домаќинот.

Нема `ln-link:destroyed` — **SYS-23**. Компонентата испраќа точно еден настан,
`ln-link:navigate` (`:46`).

### 🔵 P2 — Три expando-а по ред, со конструирани имиња

`:73` `row['lnLinkRow']`, `:75` `row._lnLinkClick`, `:78` `row._lnLinkEnter`, плус
`:117` `container['lnLinkInit']`.

Имињата се составуваат од `DOM_ATTRIBUTE + 'Row'` / `+ 'Init'`, што значи дека grep за
`lnLinkRow` во изворот не ги наоѓа — истото ограничување поради кое
`sync-ln-schemas` не гледа конкатенирани атрибути. README:312-313 ги наведува сите четири
изречно, што ја покрива дупката за читателот, но не и за алат.

### 🔵 P3 — Обсерверот вика `findElements` за секој додаден елемент на страницата

`:149-179` — `observer.observe(document.body, { childList: true, subtree: true })`, а за
**секој** додаден `nodeType === 1` јазол:

```js
findElements(node);                                       // :154
const parent = node.closest('[data-ln-link]');            // :156
```

`findElements` (`:134-143`) прави `hasAttribute` плус `querySelectorAll('[data-ln-link]')`
врз секој додаден јазол. Значи секое вметнување од која било компонента на страницата —
рендер на `ln-table`, swap на `ln-router`, клон на `ln-list` — поминува низ два DOM
пребарока на `ln-link`, дури и на страница без ниту еден `[data-ln-link]`.

`registerComponent` го прави истото за своите компоненти, така што ова не е отстапување —
но овде е трето скенирање над истите јазли, во компонента чија достапност е една демо
страница.

### 🔵 P4 — Dev проверката бара `a[href]`, кодот бара само `a`

`ln-link-dev.scss:5` — `[data-ln-link]:not(:has(a[href]))` → dev грешка.
`_initRow:70-71` — `const link = row.querySelector('a'); if (!link) return;` — **без**
`[href]`.

Значи ред чиј единствен анкор е `<a>` без `href` **се иницијализира**: добива три слушачи,
па на секој клик паѓа на `:39` (`if (!href) return;`). Dev афордансот го фаќа случајот,
но само во `[data-ln-debug]` режим; кодот трпи без збор.

Селекторот на `:35` и оној во dev SCSS-от се разликуваат за `[href]` — едно усогласување
би ги спарило.

## Отворени прашања за тебе

1. **K1 — статусната лента.** Три опции: (а) `<template data-ln-template="ln-link-status">`
   во markup, клониран при прва потреба — по `DOCTRINE.md:70`; (б) се создава **лениво**,
   при првиот `_initRow`, наместо безусловно при вчитување; (в) се задржува како е и
   `DOCTRINE.md:70` добива изречен исклучок за „страничен UI на ниво на страница" — што
   би покрило и иден сличен случај.

2. **K2 — shift/alt-клик.** `shouldIgnoreClick` не се вклопува директно (тој враќа
   „игнорирај", а овде треба гранење на три патеки), но проверката може да ги додаде
   `shiftKey`/`altKey` во `:41`. Прашањето е што **треба** да прави shift-клик: `window.open`
   без `_blank`, или едноставно `return` и препуштање на прелистувачот?

3. **K3 — `window.lnLink` како објект.** Се усогласува со останатите 49 (функција со
   `.destroy` како својство), или останува и README-то е доволна заштита?

4. **P4 — `a` наспроти `a[href]`.** Dev проверката и кодот бараат различно. Кое е точното?

5. **K5 — `_hideStatus()` во `_destroyContainer`?** Една линија, и ја затвора единствената
   патека каде лентата може да остане заглавена.
